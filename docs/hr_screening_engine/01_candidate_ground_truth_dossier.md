## 3. Официальный enterprise-стаж (ООО «БТЛаб»)

* **Период работы:** Январь 2018 — Апрель 2025 (**7 лет 4 месяца непрерывного стажа**).
* **Юридическое подтверждение:** Электронная выписка **СТД-СФР** с портала Госуслуг с усиленной квалифицированной электронной подписью (ЭЦП).
* **Компания:** ООО «БТЛаб» (Аккредитованная IT-компания, разработчик корпоративных систем документооборота).
* **Должность:** Java Backend Developer $\to$ Ведущий разработчик Java.
* **Масштаб систем:**
  * Корпоративные системы электронного документооборота (СЭД / ECM) для крупных государственных и коммерческих заказчиков.
  * База данных: **15+ млн документов** в хранилище, ежедневный транзакционный оборот.
  * Пользовательская база: **5 000+ активных пользователей**.
* **Ключевые инженерные результаты:**
  * Декомпозиция монолитного ядра СЭД: выделил 4 независимых микросервиса (шлюз, процессинг, нотификации, аудит) на Spring Boot и PostgreSQL, сократив релизный цикл с 2 недель до 1 дня через GitLab CI.
  * Проектирование асинхронного транспорта на **Apache Kafka и RabbitMQ** с гарантией At-Least-Once и идемпотентностью.
  * Интеграция с государственными шинами **СМЭВ 3.x и МЭДО** через RabbitMQ и Resilience4j (Retry, Circuit Breaker).
  * Глубокая оптимизация PostgreSQL 16: устранение дефектов N+1 (EntityGraph, `JOIN FETCH`), секционирование таблиц по годам, покрывающие B-Tree индексы `INCLUDE`, ускорение тяжелых выборок p95 с 520 мс до 45 мс.
  * Тестирование: построение тестового контура на **Testcontainers** (PostgreSQL, Kafka в Docker) с поднятием покрытия критических путей до 82%. Нагрузочные испытания в JMeter.
* **Причина ухода:** За 7+ лет ключевые архитектурные вызовы были закрыты, система перешла в фазу плавной поддержки. Осознанный переход к актуализации квалификации под новейший стек (Java 21, Spring Boot 3, Kafka KRaft, pgvector). Расставание на абсолютно позитивной ноте.

## 4. R&D-период, актуализация квалификации и Showcase (2025 — 2026)

* **Период:** Май 2025 — по настоящее время (**14 месяцев**).
* **Формат:** Авторский независимый pre-revenue R&D проект (Showcase / Proof of Work).
* **Репозиторий проекта:** `https://github.com/izhukov-dev/event-ingestion-platform` (100% открытый код, тесты, C4-диаграммы, ADR).
* **Архитектурная топология:** Dual-Service Topology (2 независимых сервиса):
  1. `ingestion-service`: Сборщик I/O на **Java 21 (Project Loom Virtual Threads)**, Spring Boot 3.4, Jsoup, SSRF-щит, Transactional Outbox (PostgreSQL 16) с CTE-лизингом (`SKIP LOCKED`), публикация в Kafka KRaft.
  2. `core-platform-service`: Модульный монолит на Spring Modulith 1.3+ и Spring AI 1.1.8. Идемпотентный консьюмер Kafka, гибридный векторный поиск (FTS + **PostgreSQL pgvector** с HNSW-индексом на `halfvec(1536)` через Reciprocal Rank Fusion), двухуровневое кэширование (Caffeine L1 + Redis L2 с вероятностным алгоритмом **XFetch**).
* **Проверенные нагрузочные характеристики (k6):**
  * Пропускная способность: **2 154+ RPS sustained** (пики до **2 500 RPS**).
  * Задержка: $p50 = 12.2\text{ мс}$, $p95 = 28.4\text{ мс}$, $p99 = 52.1\text{ мс}$.
  * Уровень ошибок: **0.000%** на дистанции > 1 300 000 HTTP-запросов.
* **Инженерные инварианты:** Zero-Mock Wire Parity (только реальные контейнеры Testcontainers: Postgres, Kafka, Redis), фиксация границ слоев через ArchUnit.
