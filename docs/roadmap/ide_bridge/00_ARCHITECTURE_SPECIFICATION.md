# IntelliJ IDE Companion Bridge: Архитектурная спецификация (SOTA Late 2026)

> **Статус**: Проектирование (Ветка: `feature/ide-bridge`)  
> **Область применения**: Секции практики (Machine Coding / LLD, Concurrency Lab, Refactoring Katas, Spring Transaction Lab).  
> **Ключевой инвариант**: 0% нагрузки ИИ на рабочую станцию, 0 новых постоянных процессов на VPS (1.8 GB RAM), нулевой технический долг (без плагинов для JetBrains SDK).

---

## 1. Контекст, мотивация и решаемая проблема

### 1.1. Ограничения веб-редактора в сложных инженерных задачах
Для задач уровня Middle+/Senior (многопоточные структуры данных, архитектура LLD на 5+ классов, рефакторинг спагетти-кода, транзакции Spring):
- Браузерный редактор Monaco не обеспечивает полноценного статического анализа Java 21, навигации по исходникам JDK (`Ctrl+B`), глубоких структурных рефакторингов (Extract Method, Inline, Safe Rename across files) и мышечной памяти хоткеев IntelliJ IDEA.
- Локальный запуск unit-тестов через зелёную стрелку `@Test` в IDE занимает **< 50 мс** на локальной JVM, в то время как удалённый прогон через Docker-песочницу требует сетевого roundtrip (1–2 сек).

### 1.2. Проблема семантического разрыва (The Semantic Gap)
Инфраструктурные утилиты файловой синхронизации (Mutagen, rsync, SSHFS) синхронизируют голые байты файловой системы, но слепы к:
- Доменной модели платформы (ID активной задачи, сессия пользователя, черновики в SQLite).
- Восприятию ИИ-напарника (контекст диалога Gemini Live WebSocket, активный файл, выделение кода).
- Переключению между 70+ задачами каталога.

### 1.3. Решение SOTA Late 2026
Паттерн **Local Companion Bridge (Доменный прикладной мост на Loopback WebSocket `127.0.0.1`)**:
- Легковесный скрипт `bridge.mjs` (Zero-Dependency на чистом Node.js 20/22) запускается в папке проекта.
- В 1 клик прямо из UI скачивается самодостаточный `.zip` архив с готовым `pom.xml` (Java 21, JUnit 5, AssertJ).
- Мост соединяется с открытой вкладкой браузера через `ws://127.0.0.1:41789`.
- Браузер выступает в роли **AI Cockpit / Voice HUD**, мгновенно транслируя изменения кода в Gemini Live (`createCodeFrame`), пока разработчик кодит в IntelliJ IDEA.

## 2. Системные инварианты

| Инвариант | Требование | Механизм обеспечения |
| :--- | :--- | :--- |
| **Инвариант 0 (VPS 1.8 GB RAM)** | Никаких процессов IDE/бэкграунд-хостов на сервере. | Код пишется и компилируется локально; на VPS работает только штатная Docker-песочница проверки. |
| **Инвариант 1 (0% Local AI)** | Никаких локальных моделей/LLM на ноутбуке. | Все модели (Gemini Live, Text, TTS) работают строго через LiteLLM Proxy в облаке Google. |
| **Инвариант 2 (Zero-Dependency Bridge)** | Никаких `npm install` и сотен мегабайт `node_modules`. | Мост написан на нативных Node.js API (`node:fs`, `node:crypto`, глобальный `WebSocket`). |
| **Инвариант 3 (Zero Data Loss)** | Каждое сохранение в IDE надёжно персистится. | Связка с существующей 3-Tier системой: LocalStorage (Tier 1) $\rightarrow$ SQLite Sync (Tier 2). |
| **Инвариант 4 (Loopback Security)** | Изоляция локального порта. | Мост биндится строго к `127.0.0.1`, проверяет заголовок `Origin`, запрещает удалённые подключения. |
| **Инвариант 5 (Echo & Race Immunity)** | Защита от бесконечных циклов перезаписи. | Хэширование файлов (`fastHashCode`/SHA-256) и фильтр источников (`origin: 'ide' \| 'web'`). |

## 4. Разделение ответственности компонентов

1. **`bridge.mjs` (Локальный агент)**:
   - Поднимает WebSocket-сервер на `127.0.0.1:41789`.
   - Наблюдает за директорией `src/` через нативный `fs.watch`.
   - Дебаунсит события диска (120 мс) и фильтрует мусорные файлы (`.idea/`, `target/`, `.git/`).
   - Принимает из веба обновления (если задача переключена или сброшена) и атомарно записывает их на диск.
2. **`useIdeBridge.ts` (React Hook во фронтенде)**:
   - Слушает локальный сокет `ws://127.0.0.1:41789`.
   - При получении `FILE_UPDATED`:
     - Обновляет Zustand `practiceWorkspaceFiles`.
     - Вызывает `DeicticGroundingManager.createCodeFrame` для Gemini Live WebSocket.
     - Передаёт управление в `useWorkspaceAutosave` для сохранения в SQLite.
3. **`IdeBridgeModal.tsx` (UI Onboarding Modal)**:
   - Кнопка скачивания предсобранного `.zip` архива задачи.
   - 3-шаговая инструкция с авто-детектом ОС (Windows / Linux / macOS).
   - Интерактивный индикатор подключения в реальном времени (`🟡 Ожидание` $\rightarrow$ `🟢 Подключено`).
