# 07. Bug Hunt Arena Specification

> **Версия**: 2.0 (Сентябрь 2026)  
> **Статус**: Production Ready  
> **Роут**: `/` -> Студия: Вкладка `incidents` (при `activeTopicBugHunt`)

---

## 1. Назначение и концепция
Режим интерактивной охоты на скрытые дефекты (Production Bug Hunting) в реальном Java 21 / Spring Boot коде. В отличие от синтетических тестов, кандидат сталкивается с «грязным» производственным кодом, содержащим тонкие архитектурные баги, утечки ресурсов, гонки данных или нарушения контрактов.

---

## 2. Диалоговый движок и роли ИИ
* **Транспорт**:
  * **Голосовой**: WebSocket `/ws/live?sessionType=tutor&tutorMode=bug_hunt&topic={topicId}` через `LiteLLM_Proxy`.
  * **Текстовый**: REST/SSE `/api/bughunt/probe` и `/api/bughunt/generate`.
* **Роль ИИ**: Socratic Production Tech-Lead.
* **Поведение ИИ**:
  * Не подсказывает баг напрямую. Задает наводящие вопросы по профилю нагрузки, поведению пулов и крайним случаям (Socratic Probing).
  * Реагирует на tactile barge-in, синхронизируется с выделением кода в редакторе (Selection Focus Grounding).
  * Пресекает галлюцинации и утечки правильного ответа через AST Tree-Edit Distance Guard.

---

## 3. Режимы тренировки (Workout Presets) & Фокус дефектов
1. **Exhaustive («Полный охват»)**: Методичный последовательный разбор подтем до 100% покрытия.
2. **Senior Multi («Senior Review»)**: Хардкорный режим — ровно 2 скрытых дефекта в одном продакшен-классе (например, нарушение потокобезопасности + утечка памяти).
3. **Random («Разминка»)**: Бесконечный поток задач для быстрого поддержания формы.

**Категории дефектов**:
* Java Streams API & Collectors.
* Многопоточность, Virtual Threads & Loom.
* Тестирование, Seams & Pitest.
* Утечки памяти & Вычислительная сложность $O(N^2)$.
* Spring AOP, Динамические прокси & Транзакции.
* Контракты `equals`/`hashCode` & Мутации коллекций.

---

## 4. Рабочее пространство и UI/UX (SOTA 2026 Non-Modal)
* **Основная панель**: Двухколоночный интерфейс с подсветкой синтаксиса, номерами строк и селектором подозрительных блоков.
* **Voice HUD**: Интегрированный блок голосовой связи с отображением RMS Db, статусов `isThinking`, `isUserSpeaking`, `isAiSpeaking` и кнопкой отправки по шагам.
* **Memory Radar Drawer**: Радар когнитивных пробелов кандидата по текущей теме.
* **TaskRecoveryCard**: Механизм мгновенной деградации и восстановления при ошибках сети или 429/503 от апстрима (Full Jitter Backoff + таймер повтора).

---

## 5. Инварианты безопасности и устойчивости
1. **Zero-Phantom Fallback**: При недоступности LLM запрещено отдавать фиктивные задачи, маскируя их под сгенерированные. Ошибка явно обрабатывается через `TaskRecoveryCard`.
2. **Selection Grounding**: При клике на строку кода или выделении фрагмента контекст выделения мгновенно инжектируется в голосовую сессию (`[ФОКУС ВНИМАНИЯ: ...]`).
3. **AST Validation**: Фиксация исправления проверяется компиляцией и тестами в in-memory песочнице (< 100 мс).
