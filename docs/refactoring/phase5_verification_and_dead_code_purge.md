# Этап 5: Очистка Мёртвого Кода и Комплексная E2E-Верификация

> **Цель:** Безвозвратно удалить устаревшие дубликаты и осколки LiveKit, убрать неиспользуемые зависимости, прогнать полный регрессионный тест всех четырех голосовых арен и зафиксировать эталонное состояние кодовой базы в CI/CD.

---

## 1. Полный реестр удаляемого мёртвого и экспериментального кода

В ходе неудачной попытки внедрить LiveKit образовались хвосты как на фронтенде, так и на бэкенде. На этапе 5 они вычищаются полностью:

### Фронтенд:
| Удаляемый артефакт | Причина удаления |
| :--- | :--- |
| `frontend/src/hooks/useLegacyLiveAudioSession.ts` | Полностью замещен каноническим хуком `useLiveAudioSession.ts`. |
| `frontend/src/hooks/useLiveKitAudioSession.ts` | Экспериментальная ветка WebRTC (порт 7880), вызывавшая таймауты. |
| Зависимость `livekit-client` из `frontend/package.json` | Больше не используется, разгружает `node_modules` и бандл на ~400 КБ. |

### Бэкенд:
| Удаляемый артефакт | Причина удаления |
| :--- | :--- |
| `backend/src/services/livekitAuthService.ts` | Генерация токенов LiveKit больше не нужна. |
| `backend/src/routes/voice.ts` | Маршрут `/api/voice/livekit-token` удаляется (или заменяется заглушкой 410 Gone). |
| Удаление роута из `backend/src/server.ts` | Убираем `app.use('/api/voice', ...)` и секцию `livekit: { ... }` из `/api/config`. |
| Зависимость `livekit-server-sdk` из `backend/package.json` | Очистка серверных зависимостей. |
| Переменные `LIVEKIT_*` из `backend/src/config/env.ts` и `docker-compose.yml` | Инфраструктурный мусор. |

### Скрипты:
| Удаляемый артефакт | Причина удаления |
| :--- | :--- |
| `scripts/test_livekit_e2e.py` | Устаревший тест WebRTC room connection. |
| `scripts/update_agent_main.py` | Вспомогательный скрипт генерации Python livekit-агента. |

## 2. Комплексная матрица E2E-регрессионного тестирования

Перед финальным пушем в `main` выполняются 5 сценариев проверки:

### Сценарий 1: Голосовой квиз по Spring Framework (Пакетный режим)
1. Открыть тему «Spring Framework (27 вопросов)».
2. Нажать «Голосовое собеседование».
3. Проверить:
   - В лобби нажать «Начать интервью».
   - ИИ произносит вопрос голосом без искажений.
   - Микрофон активируется сразу после окончания реплики ИИ.
   - Тактильный Barge-In: клик по центральному шару во время речи ИИ мгновенно заглушает звук и включает запись кандидата.
   - Завершить ответ $\rightarrow$ отображается карточка 5-секундного отсчета с новой объяснимой рубрикой баллов 35/35/30 и штрафами `-X б.`.
   - Пройти 3 вопроса подряд в режиме hands-free.
   - Проверить background Deepgram STT: в карточке есть дословный текст ответа кандидата.
   - Обновить страницу F5 $\rightarrow$ убедиться, что сессия восстановилась из чекпоинта со всеми баллами.
   - Досрочно завершить $\rightarrow$ открывается `VoiceGrandFinaleView` с разворачивающимися аккордеонами и конфетти.

### Сценарий 2: AI-Напарник в Практике (`PracticeArena`)
1. Открыть «Практика» $\rightarrow$ задача «Modern Java 21 Idioms Lab».
2. Нажать кнопку «Голос» у AI-Напарника.
3. Проверить:
   - Соединение устанавливается за < 500 мс по адресу `wss://java.djelu.site/ws/live` (никаких таймаутов на 7880!).
   - Женский голос Аэды приветствует кандидата.
   - Попросить показать код на доске $\rightarrow$ инструмент `update_whiteboard` выводит Java-сниппет на интерактивную доску справа.

### Сценарий 3: Защита архитектуры (`SystemDesignArena`)
1. Открыть сценарий «High-Load URL Shortener (100k RPS)».
2. Активировать голосовой канал.
3. Проверить диалог со Staff-архитектором и интерактивность канваса.

### Сценарий 4: Поиск инцидентов (`BugHuntArena`)
1. Открыть задачу «Deadlock in Transfer Service».
2. Активировать голосового напарника.
3. Проверить реакцию на подсказки и фиксацию исправления бага.

### Сценарий 5: Мобильная верстка и устойчивость
1. Открыть приложение на мобильном устройстве (iOS Safari / Android Chrome).
2. Проверить:
   - Отсутствие скачков экрана при вызове клавиатуры (`100dvh`).
   - Screen WakeLock: экран не тухнет во время 5-минутного голосового ответа.
   - Переключение вкладки браузера и возврат: звук не зависает, AudioContext автоматически возобновляется.

1. Прогон `npm run build` во `frontend` и `backend`.
2. Проверка сборки Docker-образов Caddy, Backend, Sandbox.

   - Отсутствие заголовков кэширования для `index.html` (`Cache-Control: no-cache`).
