# Руководство по пошаговому тестированию: Live-синхронизация IntelliJ IDEA и AI-Напарника

> **Ветка:** `feat/wave-14-intellij-bridge-live-code-sync`  
> **Фича:** Двусторонняя синхронизация правок кода из IntelliJ IDEA с AI-Напарником в Практике через `bridge.mjs` и динамический `read_file`.

---

## 📋 Предварительная подготовка

1. Убедитесь, что CI/CD успешно завершил деплой ветки на сервер.
2. Откройте в браузере платформу и перейдите в **Практику** (любая практическая задача, например, LLD или баг-хантинг с кодом на Java).
3. Запустите локальный IDE Companion Bridge (`node bridge.mjs` или плагин в IntelliJ IDEA).
4. Убедитесь, что индикатор моста IDE в интерфейсе практики перешел в статус **Подключено** (зеленый значок).

---

## 🧪 Тест-кейс 1: Базовое подключение и стартовое состояние

1. Нажмите центральную кнопку и подключите **Голосового AI-Напарника**.
2. Дождитесь вступительного приветствия от Напарника.
3. Скажите голосом:
   > *"Привет! С чего начнем решение задачи?"*
4. **Ожидаемый результат:** Напарник отвечает голосом по контексту задачи, не молчит и не прерывается.

---

## 🧪 Тест-кейс 2: Добавление нового метода в IntelliJ IDEA

1. Перейдите в IntelliJ IDEA в файл решения (например, `Solution.java`).
2. Допишите новый метод, которого изначально не было в шаблоне:
   ```java
   public boolean validateOrder(String orderId) {
       if (orderId == null || orderId.isBlank()) {
           throw new IllegalArgumentException("Order ID cannot be empty");
       }
       return true;
   }
   ```
3. Сохраните файл в IntelliJ IDEA (`Ctrl + S` / `Cmd + S`).
4. В браузере обратите внимание, что веб-редактор отобразил изменения из IDE.
5. Голосом обратитесь к AI-Напарнику:
   > *"Я написала в IntelliJ новый метод validateOrder. Посмотри на реализацию, что думаешь?"*
6. **Ожидаемый результат:**
   - Напарник **НЕ** говорит по старой версии шаблона.
   - Напарник мгновенно вызывает чтение файла `read_file` и вслух голосом комментирует именно метод `validateOrder`, проверяя валидацию и выброс исключения `IllegalArgumentException`.

---

## 🧪 Тест-кейс 3: Изменение существующей логики в IntelliJ IDEA

1. В IntelliJ IDEA измените логику метода `validateOrder`, например:
   ```java
   public boolean validateOrder(String orderId) {
       // Добавили проверку длины идентификатора
       if (orderId == null || orderId.length() < 5) {
           throw new IllegalArgumentException("Order ID must be at least 5 characters");
       }
       return true;
   }
   ```
2. Сохраните файл (`Ctrl + S` / `Cmd + S`).
3. Голосом скажите:
   > *"Я изменила условие в методе validateOrder, добавила ограничение на длину строки. Взгляни, теперь логика корректна?"*
4. **Ожидаемый результат:**
   - Напарник читает обновленный файл и голосом обсуждает проверку на длину не менее 5 символов.
   - Напарник не повторяет приветствие и не переспрашивает заново контекст.

---

## 🧪 Тест-кейс 4: Мультифайловый проект (если применимо к задаче)

1. Если задача содержит вспомогательный класс/интерфейс в проекте (или добавьте второй класс/запись `OrderRecord`):
2. Спросите напарника:
   > *"Посмотри в файлах проекта класс заказа, какие поля там объявлены?"*
3. **Ожидаемый результат:**
   - Напарник находит файл через `read_file` независимо от относительного пути (`src/main/java/...` или плоский путь) и голосом перечисляет структуру.

---

## 🧪 Тест-кейс 5: Отсутствие деградации звука и стабильность сессии

1. Проведите диалог из 4-5 последовательных реплик, продолжая обсуждать архитектуру и граничные случаи.
2. Проверьте:
   - Нет ли задержек и заиканий звука.
   - Нет ли зависания в состоянии «Думает...».
   - Нет ли обрыва сокета или ошибки квоты 1011.
   - При тактильном клике на прерывание (barge-in) микрофон перехватывается моментально.
